### [feature] Canonical tokens package (pipa-atlas PRD Phase A)

**PR:** #1

**Summary:**
First content: the pipa design tokens extracted verbatim from pipa-web into a
shared, git-dep-installable package, ending per-consumer token recoding
(pipa-web local today, pipa-app-official modernization planned its own pass,
pipa-atlas starting fresh). No registry, no build step.

**Files Changed:**

- `tokens.css` — verbatim copy of `pipa-web/styles/tokens.css` (two-tier tokens, light + dark)
- `theme-bridge.css` — verbatim extract of the `@theme inline` block from `pipa-web/app/globals.css`
- `package.json` — name/exports/files for `npm i github:Sapien-Technologies/pipa-design-system`
- `README.md` — consumption contract: install, import order, change process, both-themes rule, and the explicit pipa-web non-adoption guard (post-S21 only)

**Solution:**
Extraction over rewrite: both files are byte-copies of the production source so
adoption is a path change, never a visual change. The README carries the change
process (edits land here first; consumers bump the git ref) and the deliberate
pipa-web deferral so no agent wires it into pipa-web before the S21 cutover.

**Testing Notes:**
Live git-dep install validated from a scratch project against the pushed
branch: `npm install git+https://github.com/Sapien-Technologies/pipa-design-system.git#feat/tokens-package`
→ package ships all four files, both `exports` entries resolve. Verbatim copy
verified by construction (`cp` from the pipa-web checkout at `origin/main` parity).
